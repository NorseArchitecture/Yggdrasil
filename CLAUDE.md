## 1. What This Repository Is

Yggdrasil is **connective tissue** — `Norse.Hosting`: the web, worker, and migration service chassis (`Norse.Hosting.Web.Server`/`.Web.Client`/`.Web.Components`/`.Worker`/`.Migrations.Service`/`.Stories.Client`/`.Stories.Server`) and the deployables built on it. It hosts the runtime endpoints that Bifröst composes but never provides itself. In the dependency chain it rides on Midgard and everything below; Himinbjörg and Heimdall ride above it. `Hosting.Stories.Client`, `Hosting.Web.Client`, and `Hosting.Web.Server` directly reference Midgard's `Infrastructure.Components.Theme.FluentUI` for theming.

This repo now carries seven source projects wired into `Yggdrasil.slnx`: `Hosting.Web.Server`, `Hosting.Web.Client`, `Hosting.Web.Components`, `Hosting.Worker`, `Hosting.Migrations.Service`, and the `Hosting.Stories.Client`/`Hosting.Stories.Server` pair added 2026-07-12 to host Bragi's `DesignSystem.Stories` catalog (`../Glitnir/docs/Platform/specs/2026-07-12-designsystem-stories-hosting-design.md`). **`Hosting.Migrations.Service` is live** — Task 9 of the cross-realm migrations framework rollout (`../Glitnir/docs/Platform/plans/2026-06-28-migrations-framework-identity-schema.md`) replaced its `Placeholder.cs` for real. `Program.cs` is now exactly three lines — `Host.CreateApplicationBuilder`, `builder.AddNorseMigrations()`, `RunAsync()` — and never changes regardless of how many bounded contexts join the platform, because `AddNorseMigrations()` is the source-generated extension from Urðarbrunnr that discovers every contributor at compile time. This is deliberate scaffolding, not the deployable's permanent shape (see `../Glitnir` memory on the temporary chassis) — a lift-and-shift wave is expected once the hosting abstractions this realm is waiting on land for real. **`Hosting.Stories.Client`/`.Stories.Server` are also live** — the BlazingStory catalog host, dockerized and published to `ghcr.io/norsearchitecture/hosting/stories`.

**The `Account`/`Manage` Razor page tree that originated here has relocated out** — `Hosting.Web.Server` no longer ships it. Login/Register now live in Heimdall's `AuthN.Components.FluentUI`, headless Logout in Heimdall's `AuthN.Components`, and the rest of the tree (`ExternalLogin`, `Manage/*`, `ConfirmEmail`, `ForgotPassword`, `ResetPassword`, passkeys) in Himinbjörg's `Identity.Web.Server` — Himinbjörg's own record tracks that move as in-progress, not finished, but from this repo's side the pages are simply gone; `Hosting.Web.Server`'s `Components/` now holds only `App.razor`, `_Imports.razor`, `Layout/ReconnectModal.razor`, and `Pages/Error.razor`. Persistence is real, not stubbed — `PlaceholderUserStore` no longer exists anywhere in this repo; `Program.cs` calls Himinbjörg's `AddNorseAuthenticationService(norseIdentityConnectionString)`, which wires `NorseIdentityDbContext` (Npgsql) and ASP.NET Core Identity with the `NorseSignInManager` override against a real Postgres `norse_identity` connection string. `IdentityRevalidatingAuthenticationStateProvider`, `IdentityRedirectManager`, `IdentityNoOpEmailSender`, and `MapAdditionalIdentityEndpoints` are Himinbjörg types this project registers/calls, not code it authors. What `Hosting.Web.Server` itself now carries: the composition root (`Program.cs`) and the gRPC wiring for `IAuthenticationService` (Himinbjörg's own service, injected directly — no generated gateway sits between component and service anymore). The gateway-generator machinery this section used to describe (`EnvelopeHydrationState`, Asgard's `GatewayGenerator`/`NorseGatewayEmissionMode`, the generated `AuthenticationInProcessGateway`/`AuthenticationWireGateway`) is deleted outright — retired platform-wide 2026-07-27 in favor of a hand-rolled mediator pipeline (`../Glitnir/docs/Platform/specs/2026-07-27-mediator-pipeline-retires-gateway-design.md`). `Program.cs` calls Midgard's `AddNorsePipeline()` (behaviors + `Sender` + `IPrincipalAccessor`, plain DI, no generator involved) and `AddNorseCodeFirstGrpc()`/`MapNorseGrpcServices()` — Midgard's generated wiring registers the three-interceptor stack (`UnhandledExceptionInterceptor` → `PrincipalSeedingInterceptor` → `OutcomeServerInterceptor`), enables gRPC-Web, and maps `AuthenticationService` (Himinbjörg's `[ServiceContract]` implementation) directly — no `MapGrpcService<T>` hand-wiring, no `MapDeferredSignIn` gateway shim. This AuthN wiring is in progress on `feature/hosting-web-server-authn`, not yet merged to `master` — treat it as current-but-moving, not a settled shape. `Hosting.Web.Components` carries real template pages (`Counter`, `Home`, `Weather`, `Auth`, `NavMenu`/`MainLayout`) plus routing/theme wiring, and now also composes the circuit safety net: an `ErrorBoundary` in `MainLayout` renders the shared `Problem`/Fault UI instead of letting a lifecycle exception tear down the circuit, and `LoggingCircuitHandler` (registered in `Program.cs`) logs circuit lifecycle faults with the platform's correlation vocabulary. `Hosting.Web.Client` is no longer a stub either — it wires a browser-side gRPC-Web channel straight to the generated `IAuthenticationService` client proxy (`AddNorseGrpcClients`, Midgard's client wiring generator), with `OutcomeClientInterceptor` as the sole decoder of the wire response back into `Outcome<T>`, plus `BrowserCredentialsHandler` (sets `credentials: include` so the auth cookie survives) and FluentUI theming/auth-state deserialization; only `Hosting.Worker` remains the genuine minimal stub: `Placeholder.cs` covering both branches of a ternary (so CI coverage is well-defined from day one) and a `Program.cs` that compiles and runs clean with no hosted services. `Hosting.Worker` is replaced wholesale when the hosting abstractions from Asgard and Midgard land. Every subsequent implementation plan for this realm follows the same discipline: brainstorm → spec → plan in `../Glitnir/docs/Yggdrasil/`, greenlit by the human, then code. Each plan's REQUIRED SUB-SKILL line names `superpowers:subagent-driven-development` as the default (not a recommendation among equals — `executing-plans` is the narrow fallback for separate-session review checkpoints) paired with `superpowers:test-driven-development` — implementation here is subagent-orchestrated and test-driven, never one without the other (`../Glitnir/CLAUDE.md` §2.8).
